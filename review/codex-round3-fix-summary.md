## 日期兼容策略与判断边界

新编辑必须满足：日期均为有效日历日期，在 2000-01-01 至 2100-01-01 范围内，开始日期不晚于初试日期，跨度最多 3660 天（约十年）。单纯限制年份仍允许一百年的范围，因此增加跨度限制。

对之前已接受但现在范围/顺序不安全的设置，读取和合并采用确定性回退：根据有效 updatedAt 的 UTC 年份（限制到 2000—2098；不属于物理时间范围时取 2026），回退为该年 1 月 1 日至次年 12 月 25 日。保留修订号、其他设置和所有学习记录；合并时将修复后的设置持久化，避免旧本地越界值再次胜出。原本就非法的日期格式等错误仍按原有规则报错，没有放宽原校验断言。

T9 的“整个热度页卡死”没有在浏览器中测得具体耗时；确定复现的是危险设置被接受并传播的路径。历史极早学习记录仍可能扩大热度图范围，本次没有改统计口径或加入热度图虚拟列表。

T8 确认了写入/解析不一致，没有把每一种字典序方向都说成必然无限 PUT；不同输入可能由云端规范化版本胜出并收敛。修复使新写入记录从源头一致，未批量重写既有历史记录。

## 未采用的建议及剩余风险

- T3 没有新增数据修订号缓存：仍全量读库并进行 O(n) 内容比较，优先避免漏掉旧版/其他窗口写入；优化的是对象引用和由此引发的统计重算。所有订阅通知也尚未完全消除。
- T4 只实施快速等值比较与五分钟前台节流，未实施 SHA/ETag/304 缓存。大备份的下载、解析、整表合并和主线程耗时仍存在；不能据此宣称大数据性能问题全部解决。
- 不支持 Web Locks 的浏览器仍采用第二轮的安全停用云端同步策略；运行旧代码的窗口仍需刷新。
- 未使用真实学习数据、真实 Token 或真实 GitHub 仓库；未进行 iOS 真机、锁屏挂起、存储回收、长期耐久及大备份性能测试。
- Dexie version(1)、科目 ID、统计算法与 UI 视觉样式未修改。本轮未删除、跳过或弱化已有测试。
