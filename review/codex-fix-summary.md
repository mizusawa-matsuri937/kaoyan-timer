## 测试变化与证据

保留原 136 项测试与上一轮新增的 26 项检查，未删除、跳过或改为预期失败。必要的适配如下：

1. `expectedUpdatedAt` 改成 `expectedSession`，调用方与测试均传入原始打开快照。原有成功/拒绝断言不变；只传时间戳无法表达同版本内容冲突，因此未保留不安全的旧接口。
2. 模拟 navigator 增加 Node 24 原生 Web Locks；测试中多个 store/数据库连接共享该锁服务。没有用“直接执行回调”的假锁来规避互斥验证。
3. 组件测试补上持久化的 useRef 槽位，仍执行实际组件事件和实际 store/Dexie。不是 DOM 或完整 React 生命周期测试。
4. 一个旧 R4 用例从一次推进一小时，改成推进 6.001 秒后等待重试请求实际发出。新增的真实锁/数据库 I/O 不能靠虚拟时钟跳跃代替；原重试断言保留，并检查在第一次 5—6 秒退避后发生重试，不额外主动发起请求。
5. 两个 R1 回滚用例的注入和断言未修改；上一轮新增的四个“reload 前检查内存”回滚用例继续通过。

新增 20 项验收检查位于原 Codex 测试文件末尾，覆盖：

- 同版本旧快照删除被拒绝、最新快照可以编辑、记录消失后不自动重建。
- 在配置读事务完成后暂停：关闭操作必须等待请求启动临界区，但本地计时仍能执行。
- 已发出的 PUT 不返回时，另一窗口仍可完成关闭；旧 GET 返回后不能启动 PUT。
- 关闭后以相同配置重开，旧任务仍不能上传；等待锁的任务可取消；等待锁超时后可以恢复。

## 兼容性和仍需验证的边界

- **浏览器能力：** 云端同步现在要求 Web Locks。不支持时明确提示升级浏览器，暂停同步；本地计时、文件导入导出及关闭备份可继续使用。等待锁最多 10 秒，超时提示重试，不强抢另一个窗口的锁。
- **旧版窗口：** 跨窗口互斥要求参与者遵守同一锁协议。更新后需刷新仍打开的旧版窗口；无法让已经在运行的旧 JavaScript 自动遵守新锁。已在关闭之前发出的网络请求也无法承诺撤销服务端结果。
- **修订号范围：** 普通旧备份仍兼容。`updatedAt` 为非负安全整数，物理时间仍限制在 1970—2100。已经超过原 2100 时间上限的修订号需要新版解析器，旧版会拒绝此类极端备份。若人为导入 `Number.MAX_SAFE_INTEGER`，对应记录/设置可读取和导出，但修改会明确失败；本次不自动重写冲突版本或静默回退版本号。
- **设备验证：** 使用 fake-indexeddb、虚拟时间和 Node 原生锁，未在 iOS Safari/PWA 真机验证锁调度、杀后台、低存储、原生数据库挂起及 Service Worker 升级，也未进行长期耐久运行。
- **真实服务：** 所有数据和凭据均为测试数据，网络均模拟，未访问或写入真实 GitHub 仓库。

锁协议语义参考：[W3C Web Locks](https://www.w3.org/TR/web-locks/)。真实设备行为仍需上述设备测试确认。
